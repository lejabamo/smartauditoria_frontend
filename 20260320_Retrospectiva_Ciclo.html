SmartAuditorIA — Sistema de Gestión y Auditoría de Riesgos de Información

📋 1. Qué Funcionó (Fortalezas y Logros Verificados)

Avances técnicos consolidados y validados en el entorno de producción durante los Sprints 1 y 2:

Backend y Datos (Flask + MariaDB)

  • Modelado Relacional: Entidades completas para usuarios del sistema, autenticación, activos de información y roles RBAC (ADMIN, OPERADOR, CONSULTOR).
  • Cálculo de Criticidad: Algoritmo de impacto CIA (Confidencialidad, Integridad, Disponibilidad) alineado con DAFP V7 y MIPG.
  • Seguridad de Acceso: JWT con expiración estricta y protección contra fuerza bruta por bloqueo temporal de cuenta tras 5 intentos fallidos.

Frontend y Despliegue en la Nube

  • Wizard de Evaluación: Flujo paso a paso intuitivo que guía la calificación de activos y amenazas.
  • Matriz 5x5 Dinámica: Cuadrícula visual de calor para mapeo de severidad inherente y residual (ISO 27005).
  • Despliegue Cloud en Producción: Servidor VPS OVH (IP 51.79.35.88) operativo con dominio institucional SSL (https://riesgosti.tics.sedcauca.gov.co).

⚠️ 2. Qué Dificultades se Presentaron (Retos Reales)

Obstáculos técnicos y operativos identificados durante la ejecución:

  • Compatibilidad de Dependencias en IA: Divergencias entre versiones de Python y librerías de embeddings (ChromaDB / PyTorch) en servidores virtuales con recursos limitados de memoria RAM.
  • Sincronización de Catálogo Normativo: Complejidad para estructurar los 93 controles de la norma ISO/IEC 27002:2022 en un formato uniforme apto para inferencia RAG sin generar alucinaciones en el modelo.
  • Sobrecarga Operativa en Desarrollo Individual: La simultaneidad de roles (configuración de infraestructura Linux/Nginx, desarrollo frontend React, backend Python y redacción académica) demandó una estricta priorización para no comprometer la calidad del entregable.
  • Latencia en Respuestas de Inferencia: Pruebas preliminares con modelos LLM locales evidenciaron tiempos de espera superiores a 5 segundos por sugerencia, requiriendo un esquema híbrido de caché estructurada.

💡 3. Qué Aprendimos (Lecciones Clave)

  • El Principio «Paso dado, paso asegurado»: Antes de integrar modelos avanzados de aprendizaje profundo o vector stores, es indispensable que la base de datos relacional y las APIs REST cuenten con pruebas de integración E2E automatizadas (como test_production.py).
  • Valor de la Metodología Espiral en Proyectos de IA: En sistemas RAG, iterar primero con una base de conocimiento curada (RAG v1 híbrido) permitió validar la interfaz del usuario antes de desplegar infraestructuras vectoriales complejas (RAG v2 con ChromaDB).
  • Desacoplamiento Estricto de Capas: Mantener el motor de IA (FastAPI en Oracle Cloud) separado del backend transaccional (Flask en OVH) protegió la disponibilidad de la plataforma incluso ante picos de procesamiento del LLM.

🚀 4. Qué Acciones de Mejora se Proponen

Compromisos para el siguiente ciclo y la fase de consolidación de la Tesis:

  • Acción 1 (Base Vectorial Persistente): Migrar el servicio de sugerencias hacia una instancia dedicada de ChromaDB persistente en el VPS de inteligencia artificial.
  • Acción 2 (Evaluación Cuantitativa con RAGAS): Implementar una batería de pruebas de evaluación formal de RAG midiendo Faithfulness, Answer Relevance y Context Recall sobre la norma ISO 27002.
  • Acción 3 (Automatización CI/CD con GitHub Actions): Implementar un flujo de trabajo de despliegue continuo que ejecute linter, pruebas unitarias y despliegue automatizado vía SSH al VPS ante cambios en la rama principal.
  • Acción 4 (Conector API GLPI): Desarrollar el adaptador para sincronizar activos de TI directamente desde la mesa de ayuda GLPI institucional hacia la base de datos de auditoría.

Matriz de verificación objetiva y métricas de aceptación académica:
